# 红果短剧 · 倒计时结束自动上滑（专属自动化 v0.1）

> 归属：秒跳 · App 专属功能  
> 目标 App：红果免费短剧 `com.phoenix.read`  
> 状态：v0.6 已真机全链路验证  
> 日期：2026-11-11

---

## 1. 需求

用户接受在红果短剧里看广告（免费解锁剧集），但广告不会自然结束：

- 大部分是**动态视频循环播放**
- 一部分是**直播间推流**
- 小部分是**静态图片**

广告会显示倒计时，倒计时期间底部文案是：

> 还有 6 秒上滑继续观看短剧

倒计时结束（时长不固定）后，文案变成：

> 上滑继续观看短剧

**只有这时上滑才会继续看剧**。用户希望这一刻自动上滑，而不是自己盯着看。

## 2. 真机观察（Z50 Ultra / Android 14）

抓取时间：2026-11-11 18:26–18:33。

| 项 | 观察结果 |
|---|---|
| 播放页 Activity | `com.dragon.read.component.shortvideo.impl.ShortSeriesActivity` |
| 广告载体 | **应用内全屏浮层**，与剧集同一 Activity，窗口焦点不变 |
| 广告类型 | 抖音直播带货广告（穿山甲 / Pangle 系），循环推流 |
| 广告 UI 特征 | 右上角「广告 ｜ ⋯」角标、「← 返回」、「点击进入直播间」「查看详情」「立即领取」 |
| 底部提示 | 倒计时：`1s后可继续上滑观看短剧` / `5秒后可继续上滑观看短剧`；可滑：`上滑继续看短剧` / `上滑继续观看短剧` |
| 广告时长 | 不会自然消失，倒计时结束后广告继续循环，必须上滑 |
| 上滑实验 | 手动上滑后广告消失，进入剧集播放（画面显示第 6 集），动作有效 |
| 节点树 | 广告播放时 `uiautomator dump` 失败；自研服务实测可读到「广告」「上滑继续观看短剧」等节点文本 |

**异常观察**：上滑前标题是「第 1 集」，上滑后是「第 6 集」。可能是广告期间剧集在后台继续推进（待确认）。

**节点实测（19:00）**：广告浮层出现时，无障碍树包含 `广告`、`际华运动旗舰店`、`飞行夹克来回了`、`上滑继续观看短剧`、`全屏观看`、`发弹幕`。文案判定可行；「广告」角标的半透明 / 正常颜色是视觉样式，无障碍 API 读不到透明度，只能作辅助特征。

**二次实测（19:17）**：另一类直播带货广告的倒计时和「上滑」提示**完全不在无障碍树里**（画面绘制在 SurfaceView 上），节点路径失效。改为：无障碍服务 `takeScreenshot` 截屏 + ML Kit 中文 OCR 读取底部提示，一次成功。最终采用「**节点优先 + OCR 兜底**」双路识别。

**防重滑（实测踩坑）**：OCR 文案在滑走后会短暂残留，如果只用固定冷却，同一条广告会被连续滑 4 次、连跳多集。必须用「提示消失 / 新一场倒计时开始」作为下一次上滑的解锁条件，OCR 与节点共用同一状态。

## 4. 触发模型（提示文案驱动）

### 4.1 核心判定

在红果 `ShortSeriesActivity` 前台时，读取活动窗口节点树里的底部提示文案：

| 文案状态 | 判定 | 动作 |
|---|---|---|
| 含「上滑」+「短剧」，且含 `数字 + s/秒` | 倒计时中（如 `5秒后可继续上滑观看短剧`） | 继续等 |
| 含「上滑」+「短剧」，且不含数字/秒/倒计时 | 可以上滑（`上滑继续看短剧` 或 `上滑继续观看短剧`） | 触发上滑 |
| 无提示、也无广告特征 | 不在广告里 | 不动作 |

> 归一化规则：去掉所有空白字符后再判断；文案前后可能有图标节点（如 ⌃），不影响匹配。
> 注意：倒计时用 `s` 和 `秒` 两种单位；可滑文案有「看短剧」和「观看短剧」两种写法，必须都兼容。

### 4.2 状态机

```
IDLE
  │ 检测到广告特征（「广告」角标 / 「点击进入直播间」 / 倒计时文案）
  ▼
AD_COUNTDOWN（文案含「秒」）
  │ 文案变为「上滑继续观看短剧」（无「秒」）
  ▼
READY ──等待 400ms 防抖──▶ SWIPE（上滑一次）
                              │
                              ▼
                         VERIFY（2s 内页面变化？）
                           │ 是            │ 否
                           ▼               ▼
                        COOLDOWN        重试 1 次（间隔 5s）
                        （10s）              │
                                          失败则放弃并记录
```

### 4.3 兜底：读不到倒计时文案时

部分广告（静态图、特殊 SDK）可能没有可读的倒计时节点，此时：

- 检测到广告特征后启动 15 秒兜底计时
- 计时到点且广告仍在 → 上滑
- 期间如果读到了「上滑继续观看短剧」→ 立即按正规流程走

### 4.4 防误滑（硬性规则）

1. **必须先进入广告状态**（看到广告特征或倒计时文案），否则永不触发。
2. 文案仍含「秒」时绝不滑。
3. 同一广告只滑一次；冷却 10 秒。
4. 上滑后校验页面变化（集数标题 / 节点文本变化），无变化则只重试 1 次。
5. 用户手动上滑 / 广告浮层消失 → 立即取消。
6. 红果退到后台 / 锁屏 → 状态复位。
7. 检测到权限弹窗、系统弹窗 → 不动作。

---

### 4.5 OCR 省电策略（已实现）

| 阶段 | 行为 |
|---|---|
| 触发 | 红果内页面切换 / 用户上滑（TYPE_VIEW_SCROLLED）/ 集数变化 |
| 探测 | 打开 5 秒 OCR 窗口，每 1.2 秒截屏识别底部提示 |
| 命中倒计时 | 解析 `N秒后` / `Ns后`，本地计时 N + 0.5 秒，**关闭 OCR** |
| 到点 | 校验当前集数未变，再执行上滑；集数变了（用户手动滑走）则取消 |
| 命中可滑文案 | 立即上滑，结束探测 |
| 未命中 | 立即停止 OCR，等下一次页面变化 |
| 兜底 | 空闲 15 秒做一次 1.5 秒短探测，防止漏掉无页面变化的广告 |

已验证：探测窗口生效、OCR 停止、倒计时解析与本地计时启动。
已验证：用调试广播模拟 4 秒倒计时，5.3 秒后执行上滑（4s + 0.5s 余量 + 轮询），日志 `SWIPE completed`。

## 5. 动作

上滑手势（`dispatchGesture`）：

```
起点：(屏幕宽 × 50%, 屏幕高 × 75%)
终点：(屏幕宽 × 50%, 屏幕高 × 30%)
时长：300ms
```

- 需要 `canPerformGestures="true"`
- 失败重试 1 次（间隔 500ms）
- 竖屏坐标按实时屏幕尺寸计算；平板横屏方向待确认

## 7. 异常与边界

| 场景 | 处理 |
|---|---|
| 倒计时文案带空格 / 全角数字 | 归一化后正则匹配 `\d+\s*秒` |
| 倒计时用「6s」表示 | 正则兼容 `(\d+)\s*(秒|s)` |
| 倒计时文案不可读（图片/自绘） | 走 15s 兜底计时 |
| 静态图广告 | 走兜底计时 |
| 广告循环播放、倒计时结束后仍在播 | 文案已变为「上滑继续观看短剧」→ 触发 |
| 用户提前手动上滑 | 取消本次，复位 |
| 上滑后页面无变化 | 重试 1 次，仍失败则记录并放弃 |
| 广告期间剧集在后台推进 | 滑一次可能跳过多集 → 需用户确认 |
| 连播多条广告 | 每条广告独立判定 |
| 红果切到直播间（用户主动点） | 不动作 |
| 切后台 / 锁屏 | 状态复位 |
| 秒跳后台被 MyOS 冻结 | 实测后台约 3 分半无心跳；需要前台服务 + 电池白名单，否则广告出现时响应会延迟 |
| 平板横屏 | 手势方向按屏幕方向适配（待确认） |

## 8. 验收标准

- [ ] 文案为「还有 N 秒上滑继续观看短剧」时，0 次触发
- [ ] 文案变为「上滑继续观看短剧」后，1 秒内完成上滑（连续 20 次 ≥ 18 次）
- [ ] 正常看剧（无广告）误滑 = 0
- [ ] 用户手动上滑后不重复滑
- [ ] 关闭开关后动作 = 0
- [ ] 切到其他 App 不触发
- [ ] 上滑后确实继续播放剧集（人工确认 20 次，成功率 ≥ 90%）

## 9. 待确认

1. 「上滑继续观看短剧」是纯文本节点，还是带图标的组合控件（决定匹配方式）。
2. 倒计时文案的完整格式（「还有 6 秒…」还是「6 秒后…」），以及是否所有广告都有。
3. 上滑后为什么是第 6 集（广告期间剧集是否自动推进）。
4. 平板横屏时红果是上滑还是左右滑。
5. 倒计时前缀文案的准确格式（「还有 6 秒上滑继续观看短剧」），需要广告从 0 秒开始抓一次。

## 10. 后续扩展

做成「触发器 → 动作」通用模型，红果只是第一条内置规则：

```json
{
  "id": "hongguo_auto_swipe",
  "packageName": "com.phoenix.read",
  "activity": "com.dragon.read.component.shortvideo.impl.ShortSeriesActivity",
  "trigger": {
    "type": "text_ready",
    "hintContains": ["上滑", "短剧"],
    "countdownRegex": "\\d+\\s*(s|秒)",
    "fallbackSeconds": 15,
    "debounceMs": 400
  },
  "action": { "type": "swipe", "from": [0.5, 0.75], "to": [0.5, 0.30], "durationMs": 300 },
  "verify": { "type": "page_changed", "timeoutMs": 2000, "retry": 1 },
  "cooldownMs": 10000
}
```

以后加新 App 只需加一条规则，不改引擎。
