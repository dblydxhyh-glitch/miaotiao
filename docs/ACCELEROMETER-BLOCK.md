# 秒跳 · 摇一摇广告治理（加速度传感器禁用）方案 v1.0

> 目标设备：努比亚 Z50 Ultra / MyOS（Android 14）
> 状态：设计稿；MyOS 特殊权限的接口细节待真机抓取确认（TBD）

---

## 0. 结论先行

1. **检测层可以完全由秒跳实现**：自采样加速度 + 前台跳转事件 + 触控证据 + 重复性，判断某 App 是否存在「摇一摇广告跳转」行为。
2. **禁用层依赖 MyOS 私有能力**：Android 没有「按应用禁用加速度传感器」的公开 API。MyOS 的「特殊权限」是厂商私有实现，第三方 App 不能假设可以直接写入名单。
3. 因此分两条路径：
   - **路径 A（推荐，立即可用）**：秒跳检测 + 生成嫌疑 + 一键跳转 MyOS 特殊权限页 + 用户确认 + 镜像名单与回滚。
   - **路径 B（仅当 MyOS 开放可写接口时）**：通过厂商 API / 可写系统设置自动拉黑。需真机验证，标注 TBD。
4. 其他安卓系统：**不能用该功能自动禁用传感器**，只能用秒跳已有的「跳转拦截 + 引导」，属于降级方案（见第 5 节）。

## 1. 任务目标拆解

### 1.1 子任务一：加速度传感器权限管理

**名单来源**

- 权威名单：MyOS「特殊权限」中该 App 的「加速度传感器」开关。
- 秒跳镜像名单（本地数据库）：包名、应用名、加入时间、证据、来源（用户手动 / 自动建议）、状态。

**状态机**

```
待确认(PENDING) ──用户确认/接口写入──▶ 已禁用(BLOCKED)
       │                                   │
       └────────用户忽略────────▶ 已忽略(IGNORED)
                                           │
                                   回滚(ROLLED_BACK)
```

**入口与跳转**

1. 秒跳「摇一摇防护」页 → 每个嫌疑 App 提供「禁止读取加速度」按钮。
2. 跳转优先级：
   - 厂商私有 Action（TBD，需抓取 MyOS 特殊权限页的 Intent）；
   - 兜底 `ACTION_APPLICATION_DETAILS_SETTINGS`（应用详情页）；
   - 再兜底 `ACTION_MANAGE_APPLICATIONS_SETTINGS`。
3. 跳转后用户手动操作；返回秒跳时提示「已完成请确认」，用户点「我已添加」写入镜像。

**自动写入（路径 B）**

- 若 MyOS 提供 AppOps / 厂商 API / 可写 Settings 键（TBD）：
  - 调用接口把包名加入禁用名单；
  - 写入后回读校验；
  - 失败则降级到路径 A。
- 约束：不假设接口存在；所有未知项标注 TBD，先做抓取再实现。

**校验与回滚**

- 若名单可读：启动时与镜像对比，修复漂移（系统侧被手动改动）。
- 若不可读：以用户确认为准，提供「我已添加 / 已移除」。
- 回滚：一键移出名单（接口或引导），记录时间与原因。

### 1.2 子任务二：摇一摇广告行为识别

**可用信号**

| 信号 | 来源 | 说明 |
|---|---|---|
| 前台跳转 | 无障碍事件 | App A → 浏览器/应用商店，8 秒内 |
| 设备摇动 | 秒跳自采样加速度 | 跳转前 2 秒的峰值、方差、方向反转次数 |
| 触控证据 | `TYPE_VIEW_CLICKED` | 跳转前 1 秒内是否有用户点击 |
| 目标特征 | 包名/URL | 浏览器/商店；广告落地页特征（可选） |
| 重复性 | 事件库 | 同一来源 App 24h 内 ≥2 次、7 天内 ≥3 次 |
| 排除项 | 白名单 | 导航、游戏、指南针、运动健康、系统应用、秒跳自身 |

**核心判定逻辑（多维打分）**

| 条件 | 分值 |
|---|---|
| 前台跳到浏览器/商店 | +40 |
| 跳转发生在 App 启动后 8 秒内 | +15 |
| 跳转前 2 秒检测到摇动特征 | +25 |
| 跳转前 1 秒无点击事件 | +10 |
| 重复命中（24h 内 ≥2 次） | +10 |
| 来源 App 在允许名单 | -100（直接排除） |

- **≥70 且重复 ≥2 次**：列入「嫌疑」，提示用户禁用；
- **50~69**：只记录，不提示；
- **<50**：忽略。
- **首次命中一律只记录**，不拉黑；不确定时默认不拉黑。

### 1.3 联动关系与执行顺序

```
检测（传感器 + 前台跳转 + 触控）
  → 打分/去重
  → 生成嫌疑（PENDING）
  → 通知或一键跳转 MyOS 特殊权限
  → 用户确认 / 接口写入
  → 镜像名单 BLOCKED
  → 持续观察 + 回滚入口
```

关键原则：**检测归检测，禁用归禁用**。检测结果永远可解释、可回滚；禁用动作必须经过用户确认（路径 A）或可验证的接口（路径 B）。

## 2. 判定规则（可操作）

### 2.1 正常使用 vs 广告跳转

| 维度 | 正常（游戏/导航/指南针/健身） | 摇一摇广告 |
|---|---|---|
| 传感器使用时长 | 持续，与前台生命周期一致 | 集中在开屏 0.5~3 秒 |
| 前台路径 | 不跳浏览器/商店 | 数秒内跳浏览器/商店 |
| 触控 | 有明确交互 | 跳转前通常无点击 |
| 触发阈值 | 大幅晃动才触发，且是游戏/导航动作 | 轻微晃动即触发 deeplink |
| 重复性 | 稳定使用，不产生跳转 | 每次开屏几乎必现 |
| 应用类别 | 地图/导航/游戏/健康 | 阅读、工具、社交、短剧等 |

### 2.2 传感器特征阈值（保守起点，需真机标定）

- 采样率：50 Hz；
- 窗口：跳转前 2 秒；
- 摇动判定（满足任一）：
  - 合加速度峰值 ≥ 2.5 g，且 0.5 秒内方向反转 ≥ 3 次；
  - 窗口内方差 ≥ 4 (m/s²)²。
- 说明：不同手机传感器量程/噪声不同，阈值需按机型标定；标定前使用保守值。

### 2.3 不确定情况

- 传感器读数为 0（全局隐私开关开启 / 无传感器）→ 只记录「无法判定」，不拉黑；
- 跳转前有点击 → 判定为用户主动，不拉黑；
- 目标不是浏览器/商店 → 不进入本流程；
- 应用类别无法确定 → 不拉黑，提示用户手动判断；
- 同一 App 只命中 1 次 → 只记录，不提示。

### 2.4 规则脚本结构（草案）

```json
{
  "id": "shake_ad_block",
  "version": 1,
  "trigger": {
    "foregroundJump": { "to": ["browser", "store"], "withinMs": 8000 },
    "sensor": { "windowMs": 2000, "sampleHz": 50, "peakG": 2.5, "reversals": 3, "variance": 4.0 },
    "noClickWithinMs": 1000
  },
  "score": { "jump": 40, "withinWindow": 15, "shake": 25, "noClick": 10, "repeat": 10 },
  "thresholds": { "suggest": 70, "logOnly": 50 },
  "repeat": { "windowHours": 24, "minHits": 2 },
  "allowlist": { "categories": ["navigation", "game", "health", "compass"], "packages": [] },
  "action": { "type": "blocklist", "mode": "confirm" }
}
```

## 3. 输出形态

### 3.1 权限配置步骤（MyOS，路径 A）

1. 秒跳 →「摇一摇防护」→ 选中嫌疑 App →「禁止读取加速度」。
2. 跳转 MyOS 特殊权限页（Action TBD；兜底应用详情页）。
3. 在该页把目标 App 加入名单，关闭「加速度传感器」。
4. 返回秒跳 →「我已添加」→ 状态变为「已禁用」。
5. 之后秒跳继续监控；若发现该 App 仍能跳转，提示复查。

### 3.2 名单管理规则

- 以包名为唯一键；
- 每条记录包含：包名、应用名、首次命中时间、最近命中时间、命中次数、证据快照（目标、传感器特征、是否有点击）、状态、来源；
- 支持手动放行（允许名单）与一键回滚；
- 支持 JSON 导入/导出，便于换机。

### 3.3 识别与自动化伪代码

```text
onForeground(pkg):
    if pkg in allowlist: return
    window = startSplashWindow(pkg, 10s)
    startAccelSampling(50Hz) while window active

onJump(from, to, now):
    if to not in browsersOrStores: return
    if now - fromStart > 8s: return

    score = 40
    if now - fromStart <= 8s: score += 15
    if shakeDetected(last2s): score += 25
    if noClick(last1s): score += 10
    if hits(from, 24h) >= 2: score += 10

    if from in allowlist: return

    if score >= 70 and hits(from, 24h) >= 2:
        addSuspect(from, score, evidence)
        notifyOrGuide(from)          # 路径 A
        # 若厂商接口可用（TBD）: autoBlock(from)
    else if score >= 50:
        logOnly(from, score)
```

### 3.4 验证与回滚

- 验证：
  - 单元测试评分逻辑（固定事件样本）；
  - 真机：模拟「启动 App + 摇动 + 8 秒内跳浏览器」，检查是否生成嫌疑（用测试 App，验证后清除）；
  - 真实广告复现（最佳）。
- 回滚：秒跳内一键移出名单；若走厂商接口则调用移除；记录原因。
- 误伤监控：游戏/导航类默认放行；用户可一键「永不处理」。

### 3.5 多种实现路径与取舍

| 路径 | 适用条件 | 自动化程度 | 风险/成本 |
|---|---|---|---|
| A. 辅助 + 跳转 | 任意安卓 | 低（需用户点几下） | 低；通用 |
| B. 厂商 API / 私有 Action | MyOS 开放接口（TBD） | 高 | 需逆向/文档；ROM 升级可能失效 |
| C. WRITE_SECURE_SETTINGS 写名单 | 名单存于可写 Settings/AppOps（TBD） | 高 | 键名未知；adb 授权；易失效 |
| D. Shizuku / root | 用户愿意折腾 | 高 | 门槛高；不适合大众 |

建议：**先做 A，同时用真机抓取 MyOS 的页面组件、Intent、Settings 键，确认 B/C 是否可行**。

## 4. 约束与边界

- MyOS「特殊权限」的具体 Action、存储位置、是否可写：**TBD**，必须真机抓取（`dumpsys`、`settings list secure/system`、Intent 抓包）。
- 第三方 App **无法读取其他 App 的传感器使用记录**；本方案是「本机运动 + 前台事件」的关联推断，不是系统级审计。
- 加速度传感器没有权限门槛；「禁止读取」是 ROM 的隐私功能，不是 Android 标准权限。
- 秒跳自身不能被加入禁用名单，否则无法采样；需在名单中排除自身。
- Android 12+ 的全局传感器隐私开关会让读数为 0，需检测并提示。
- WebView 内广告不产生包名跳转 → 本方案无法识别，只能靠已有拦截兜底。
- 结论只对「跳转型摇一摇广告」有效；不处理站内广告。

## 5. 跨安卓系统评估

| 系统 | 按应用禁用加速度 | 自动写入名单 | 辅助模式 | 说明 |
|---|---|---|---|---|
| MyOS（努比亚） | ✅ 特殊权限 | TBD | ✅ | 本方案目标平台 |
| 原生 Android 12+ | ❌ | ❌ | ⚠️ 仅应用详情 | 只有全局麦克风/摄像头隐私开关，无按应用传感器开关 |
| MIUI / HyperOS | 部分机型可能有 | ❌ | ⚠️ | 需逐机型确认 |
| ColorOS / OriginOS | 可能有隐私权限 | ❌ | ⚠️ | TBD |
| 三星 One UI | 可能有传感器权限 | ❌ | ⚠️ | 需确认 |
| 类原生 / 其他 | ❌ | ❌ | ❌ | 只能保留「跳转拦截」 |

**结论**：该功能强依赖 ROM 的隐私权限。跨系统时，秒跳只能做「检测 + 拦截 + 引导」，无法自动禁用加速度传感器；**已有的跳转拦截在任何安卓上都能缓解摇一摇广告**，传感器禁用只是 MyOS 上的增强。
